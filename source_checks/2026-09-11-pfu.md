# PFU treatment-window check — 2026-09-11

Official public source: `https://pfu.presse.no/pfu-basen/`. PFU's browser application exposes a public Algolia search-only integration. Its production bundle names the `pfu-basen_processedAtDesc` index, the selected response fields, and treatment-date filters on `processedAtTimestamp`. The adapter uses that same bounded read-only search contract. It does not require a private credential.

The approved mode is a rolling treatment window. The exact verified configuration was:

```toml
kind = "press_cases"
urls = ["https://pfu.presse.no/pfu-basen/"]
events = ["added", "changed"]
lookback_days = 30
page_size = 100
max_pages = 5
max_records = 500
max_bytes = 1000000
allow_empty = true
```

On 2026-09-11 this selected the complete inclusive UTC window from 2026-08-12 through 2026-09-11. The API reported 11 hits, one page, and the adapter obtained exactly 11 unique case numbers. Two fresh real polls with the configuration above returned 11 records each, zero alerts on the first baseline, zero alerts on the repeat, and identical full record snapshots. The case numbers were `26-073`, `26-079`, `26-089`, `26-092`, `26-098`, `26-106`, `26-107`, `26-111`, `26-119`, `26-120`, and `26-121`.

The stable identity is PFU's case number. Monitored content is medium, PFU outcome, complainant, and the optional concise conclusion. Outcomes are rendered in Norwegian: `Brudd`, `Kritikk`, `Ikke brudd`, or `Venter behandling`. Alerts identify the case and medium and describe field changes without exposing raw JSON. The adapter requests neither complaint text nor decision full text.

`processedAt` and `processedAtTimestamp` are validated against each other and define membership in the rolling window. They are treatment metadata, not publication timestamps: `published` is unset, and time-only changes do not alter the content fingerprint. Exact page numbers, page sizes, totals, page counts, record counts, types, response size, and duplicate identities are validated; an incomplete or changing result fails closed.

An empty window is valid. Removed events and complete snapshots are rejected because records eventually age out of a rolling window, which cannot prove deletion. Manual `case_numbers` are rejected so this source remains discovery-capable. This evidence covers the rolling-window mode; it does not claim full historical coverage or medium-filter mode.
