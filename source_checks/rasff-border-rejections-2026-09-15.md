# Public food and feed border-rejection summaries

The [official RASFF Window guide](https://webgate.ec.europa.eu/imsoc-guide/rasff-window-help/en/what-is-rasff-window-.html) distinguishes border rejection from alert, information and news notifications. The [public search](https://webgate.ec.europa.eu/rasff-window/screen/search) exposes a paginated summary service used by its own client. This function follows border rejection summaries rather than consumer recall notices.

The public search component supplies POST parameters `pageNumber`, `itemsPerPage`, `ordering`, `sorting`, `ecValidDateFrom`, `ecValidDateTo` and `notificationClassification`. The observed public classification catalogue maps 305 to `border rejection notification`. The adapter uses only the public summary endpoint. Authentication, private endpoints, attached documents and business-operator details are outside scope.

The final 30-day recipe returned 102 notifications across two pages of 100 and 2 records. Two real adapter polls made eight complete HTTP reads, returned zero initial/repeated alerts and produced identical complete next state. Adjacent JSON records the exact request bodies, response byte counts and hashes, and final code/configuration hashes. A separate real single-day query returned an explicit empty response with zero total elements and pages. Raw responses are not included in this repository. Forty-nine targeted synthetic contract and integration tests passed; those tests are separate from real-source evidence.

All pages in the selected date window must agree on totals. Expected page lengths, globally unique IDs and references, descending EC-validation clocks, applied class and date filters, and two complete matching window reads are checked before persistence. Invalid JSON, duplicate JSON keys, nonfinite values, malformed catalogue/country fields, unexpected redirects and configured bounds preserve prior state. Optional exact origin-country selection is applied only after all source records are validated.

Source EC-validation date/time is stored without an assumed timezone and is not treated as publication or rejection time. Product type, category, subject, notifying country, origin countries and risk decisions remain explicit source fields. Unused technical flags do not create alerts. Origin-country order is canonicalized. The source's risk label does not establish consumer exposure or distribution in Norway.

The first read is quiet. New notifications and revisions within the date window may alert once. Window absence is not evidence that a consignment was released or a notification withdrawn. Older revisions, brands, business-operator details and actual alert delivery are not established by this source check. Two equal reads do not guarantee a transactional server snapshot.
