# Regional avalanche-warning change notices

The [official NVE documentation](https://api.nve.no/doc/snoeskredvarsel/) links production API v6.3.2. Its Swagger marks the older Detail route obsolete and documents `Warning/Region/{id}/{langkey}/{startdate}/{enddate}` as a warning list. This adapter uses that current route. Source attribution and a link to the complete warning accompany every change notice. It deliberately supplies a document-change notice rather than an abbreviated hazard bulletin or local safety recommendation.

The final recipe selects Jotunheimen and Lyngen, Norwegian language, yesterday through two days ahead in Europe/Oslo. Two actual polls each returned eight whole-day records, zero alerts and identical full state. All eight current records were explicitly unassessed, with source publication ID zero. Zero is not interpreted as low danger. A separate check selected 1–3 March 2026 through the same current endpoint: two real reads each returned three assessed warnings, each with danger level 3 and substantive warning/problem content. These are historical contract checks, not current hazard evidence. The clock was overridden solely to request those explicit historical dates; source bytes were unchanged. [Evidence JSON](avalanche-warnings-2026-09-14.json) records the exact requests, hashes, module/configuration fingerprint, historical scope and link checks.

Identity is region, language and validity date. Source publication ID is a monitored field, so issuing a real assessment for a placeholder or replacing the publication for the same day changes the same record. Explicit tendency warnings remain distinct from full assessments. A day moving into the window without an assessment is stored quietly. Placeholder scheduling timestamps do not create repeated notifications. A previously assessed day becoming explicitly unassessed creates a notice without asserting that danger has ended. Missing records instead fail the whole requested window; absence never becomes an unassessed value or deletion claim.

Issued warning detail is normalized and hashed, excluding the author field. This follows changes to text, problems, advice, weather and other returned metadata without copying an incomplete bulletin into alerts or state. Administrative-list order and text whitespace are normalized; warning-list order remains significant. The adapter requires the documented detail fields, matching region/language, one distinct whole-day record for every selected date, bounded JSON and valid assessment identity. Unknown scope, missing dates, duplicate identities/JSON keys, inconsistent placeholders, incomplete issued detail, redirects and size limits fail before state advances. A changed source contract therefore requires inspection.

Seven adapter tests plus recipe/catalog tests passed (25 targeted checks). They cover quiet repeats, issued-content changes, publication-ID replacement, placeholder clock noise and assessment transitions, rolling dates, tendency warnings, incomplete multi-region atomic failures, invalid schema/dates/transport and limits. Artificial changes establish notification behavior only. The observed public index provides dated warning links; actual HTTP checks opened the matching Jotunheimen/Lyngen dates and one assessed historical Jotunheimen warning. No notifier was used for these checks. Later actual issued-warning changes and delivery remain unobserved; seasonal unassessed data does not prove present-day assessed coverage.
