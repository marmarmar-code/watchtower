# OFAC SDN list entry changes

Official source: https://ofac.treasury.gov/sanctions-list-service

The official frontend exposes a public metadata POST and an export GET. The export redirects to OFAC's public S3 bucket. The adapter permits only that exact bucket and the exact publication path obtained from metadata; temporary query parameters are excluded from evidence. It validates ZIP size, a single bounded SDN.XML member, uncompressed size, published SHA-256 and XML Record_Count before selecting entries. No credentials are required.

The publication dated 2026-09-10 contains 19388 unique entry UIDs: 9973 Entity, 7533 Individual, 1540 Vessel and 342 Aircraft. XML provides explicit types; legacy CSV's blank type is not inferred to mean Entity. Entity/Vessel selection is explicit. One recipe selects 861 Entity entries with the IFSR program; the other selects 1540 Vessel entries across programs. These are two selections of one function. All programs on selected entries remain in the monitored fields. The initial broader business candidate had 4138 entries and exceeded the default 3000-entry general history capacity; it was not used as the final recipe.

Two real polls through each final recipe and engine returned zero alerts and identical full state. Monitored fields include names, program codes, identifiers, aliases, addresses, vessel details and full XML remarks. Detail lists are sorted canonically, child UIDs must be unique, and publication metadata does not create entry changes. Synthetic regression checks also cover malformed, oversized, duplicate, mismatched and redirected input; those tests are not real change-delivery evidence.

This observes OFAC list entries, not name screening or a conclusion about guilt or the legal rules applicable to a transaction. An initial observation is not a designation date. Absence or leaving the chosen program/type scope does not produce a removal decision. XML supplies no per-entry publication date in this contract. The two final selections fit the existing default history capacity; larger custom selections require explicit capacity review. A publication changing between metadata and download fails the checksum check and preserves prior state until a later poll.

See the JSON companion for retrieval hashes and exact verification timestamps. Hosted execution and later delivery require separate evidence.
