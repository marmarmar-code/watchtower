# EU merger decision observations

The final recipe completed two real bounded public reads on 14 September 2026. Each returned 39 search documents across 10 cases, normalized to 12 logical decisions. Both local engine polls emitted zero alerts (quiet first load and unchanged repeat); full resulting states were identical. Response hashes differ because search envelopes contain volatile values. The companion JSON records the final module/configuration hashes and response sizes.

The anonymous browser configuration supplies the search client value at runtime. It is neither a user credential nor stored in configuration, state, evidence or messages. The official search API supplies merger metadata only. A single complete page must contain every reported result, at most 100 documents. Overfull, incomplete, malformed or warning-bearing responses fail before state advances. A complete empty window is valid.

The window selects cases by their last decision activity, from UTC today minus 14 days through today. Individual adoption dates can precede that window; messages explicitly describe newly observed information. Case-only records and ordinary attachments are excluded. Decision records and decision-linked attachments coalesce under the case plus decision UUID; conflicting substantive fields fail. A decision available only through a linked attachment is retained. Only adoption date, type codes and case number are monitored. Case-title corrections and search ordering do not generate alerts. Rolling windows cannot establish removals or complete historical coverage.

Case links target the official case page, not a guessed document download. The route is independently supported by indexed official content at [M.12563](https://competition-cases.ec.europa.eu/cases/M.12563) and [M.12456](https://competition-cases.ec.europa.eu/cases/M.12456). Direct HTTP reads yield an application shell; authenticated browser interaction has not been tested.

Two observed type labels are exact descriptions from the official [decision reference data](https://api.tech.ec.europa.eu/casereferencedata/1/api/v1/id/MECaseDecisionTypes/related-hierarchies?type=DECISION_TYPE), retrieved on 14 September 2026: DecisionType20310 is `139/2004 Art. 6(1)(b)` and DecisionType201316 is `139/2004 Art. 4(5) referral`. Labels affect presentation only; every alert retains the code, and unknown codes remain visible verbatim. No inferred legal outcome is added.

Verification covers malformed/incomplete windows, scope, duplicate identities, decision/attachment coalescing, conflicting metadata, quiet baseline/repeat, metadata noise, substantive type changes, unknown-code presentation, empty windows, byte limits, redirect rejection and all recipe construction. Synthetic mutations exercise guards; the two live reads establish actual source compatibility. Hosted scheduling, later real revisions and notification delivery remain separate proof requirements.
