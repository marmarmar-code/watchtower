# Public capacity-message revisions

The official UMM service links a public RSS feed at https://ummrss.nordpoolgroup.com/messages/. Anonymous complete GET responses were used; no registered API endpoint or credentials were needed. The final configured adapter was evaluated twice against real responses: 53 selected messages, zero initial alerts, zero repeated alerts and identical full state. Response hashes and code hashes are in the adjacent JSON receipt. An earlier research snapshot contained 52 selected messages. Counts describe observed windows, not fixed totals.

Every item validates its UUID/revision GUID against its official message link. Duplicate GUIDs or repeated base UUIDs fail closed. Metadata and capacity schemas are checked before selection. A message is selected when an explicit Area token is one of NO1–NO5, including cross-border pairs. The complete table for that message is retained, including any other areas it contains.

Three observed table schemas contain seven, eight or ten columns. Continuation rows have explicit empty cells, not rowspan attributes. Production tables can contain a parent unit with empty interval/capacity fields followed by subunits whose Area is blank. Ordered rows and all blank cells are preserved literally. The adapter neither assigns inherited capacities nor sums parent and child capacities. Nonblank capacity cells require an explicit MW unit. Paired interval clocks are validated without inventing a timezone; RSS publication carries its own explicit offset.

Revision, source status, publisher, source publication clocks, planned/unplanned classification, reason code and tables are monitored. Free-text reasons, remarks, asset lists and market-participant lists are excluded. General messages are outside this capability. A message is not proof of a physical power outage or restoration. Absence from the rolling feed causes no removal alert. The feed has no verified full-history or pagination contract; messages may disappear between hourly checks.

Generic synthetic tests separately exercise revisions, before/after alerts, duplicate and transport guards, invalid source fields, parent/subunit/continuation blanks, exact area selection, disappearance/reappearance, and preservation of persisted state on revision regression or inconsistent reads. They are not real-data or operational delivery evidence.
