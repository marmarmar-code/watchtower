# Classified device recall action records

Official references: [dataset overview](https://open.fda.gov/apis/device/recall/), [field definitions](https://open.fda.gov/apis/device/recall/searchable-fields/) and [pagination](https://open.fda.gov/apis/paging/).

Two complete real polls of the final 14-day recipe each returned 42 distinct product recall records across 13 event groups. Each poll fetched 25 and 17 records, matching the API total of 42, then re-read the first page. All classification dates fell within September 1–14, 2026. Dataset export date was September 10. Both polls produced zero alerts and identical full state. The six exact request URLs, byte counts and SHA-256 values are recorded in [the evidence JSON](device-actions-2026-09-14.json). No notifier was used for these checks.

Records use product_res_number as identity and retain res_event_number for grouping. The exact product recall number supports stable API sorting; sorting on cfres_id was rejected by the service and is not used. The adapter validates page size, offsets, reported totals, ordering, unique product/internal IDs, consistent export metadata and an unchanged first-page anchor. Oversized, missing, partial, duplicate, inconsistent or redirected responses fail before snapshot persistence. Classification dates cannot exceed the export date. The anchored pagination checks cannot exclude an undetected change confined to a later page while the first page and export metadata remain identical.

Monitored fields include action text, reason, cause category, product description, quantity, initial distribution and classification/initiation dates. Full normalized model/serial/batch-code text is fingerprinted without copying very large lists into alerts or state. The observed raw code list reached 107734 characters. Contact fields and recall status are omitted. Optional missing quantities and dates remain unknown.

FDA defines event_date_posted as classification date, which need not denote a new recall. Initial distribution may omit later redistribution. Data are refreshed weekly and are not evidence of current lifecycle state. This capability supports investigation of source records, not public consumer safety alerts or medical decisions. Corrections outside the classification window are not observed; absence never proves withdrawal or resolution. The separate enforcement-report dataset was researched but not implemented.

Eight focused adapter tests cover repeat silence, action/scope revisions, ignored status/contact fields, product identities within shared events, complete pagination and anchor changes, malformed/duplicate/partial pages, missing-response semantics, large code lists, inclusive date windows, nullable fields and bounded failures. The adapter, recipe, catalog and test-runtime generation checks passed 26 targeted tests; the adapter checks were rerun after the final export-date consistency check. Artificial changes prove event logic. Later scheduled repetition and actual upstream change delivery are not established by this evidence.
